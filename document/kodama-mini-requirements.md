# KODAMA mini 要件定義書（箱庭＋プレイヤー点移動＋QRタネ取得）

## 1. 概要

### 1.1 システム名
- **KODAMA mini（こだまミニ）**

### 1.2 コンセプト
QRコードで取得した「タネ」を箱庭（ミニ公園）に植え、  
箱庭の中を●（プレイヤー点）が歩くことで、  
**位置によって音が変わる “こだま的音体験” を提供する。**

### 1.3 想定利用シーン
- イベント会場
- コワーキングスペース
- カフェ・ギャラリー
- 展示会

会場に複数のQRコードを貼り、来場者がそれを読み取ることでタネを取得する。

---

## 2. 対象ユーザー・利用環境

### 2.1 対象ユーザー
- イベントや施設の来訪者  
- Googleログインができる一般ユーザー

### 2.2 利用環境
- スマートフォンブラウザ（iOS / Android）
- PCブラウザも可（開発者動作確認用）

---

## 3. 用語定義

| 用語 | 説明 |
|------|------|
| **タネ** | 音源を持つオブジェクト。QRで取得し箱庭に配置できる。 |
| **箱庭（ガーデン）** | ミニ公園のような2Dフィールド。タネとプレイヤー点を配置する。 |
| **プレイヤー点** | 箱庭内を移動する小さな●。ユーザー自身を表す。 |
| **QRコード** | 会場に貼る。読み取るとタネを取得するURLが開く。 |

---

## 4. ユースケース

### UC-01：Googleでログインする
1. ユーザーがアプリにアクセス  
2. 「Googleでログイン」  
3. OAuth認証  
4. 初回はユーザー情報をDBに保存  
5. ホームへ

### UC-02：QRコードからタネを取得
1. 現地のQRを読み取る  
2. `/seed?code=ABC123` がブラウザで開く  
3. ログイン状態を確認（未ログインならログインへ誘導）  
4. codeをDBでチェック  
5. 有効なら `user_seeds` にタネを付与  
6. 「タネを手に入れました！」画面

### UC-03：箱庭（マイにわ）を表示
1. マイにわ画面を開く  
2. ユーザーのタネ一覧を取得  
3. タネの配置位置を反映  
4. プレイヤー点を中央に表示

### UC-04：タネを箱庭に植える
1. 未配置タネ一覧を表示  
2. ユーザーがタネを選択  
3. 箱庭の任意の位置をタップして配置  
4. `pos_x`, `pos_y` をDBに保存  
5. 箱庭に反映

### UC-05：プレイヤー点を移動する
1. 十字キーUIを表示  
2. ユーザーがボタンを押す  
3. プレイヤー点が一定量移動  
4. 箱庭外に出ないよう制限  
5. キーボード矢印キーにも対応（PC）

### UC-06：音の聞こえ方が位置で変わる
1. プレイヤー点移動ごとに各タネとの距離を計算  
2. 音量を距離に応じて変更（近いほど大きい）  
3. 離れたタネは無音  
4. 余裕があればステレオパンにも反映

## 5. 機能要件

### 5.1 認証
- FR-001：Google OAuthログイン  
- FR-002：初回ログイン時にユーザー情報をDB保存  
- FR-003：各APIで認証ユーザーを参照  
- FR-004：ログアウト機能（任意）

### 5.2 QRタネ取得
- FR-010：`code` パラメータを受け取りDB検索  
- FR-011：有効ならタネを `user_seeds` にINSERT  
- FR-012：同一codeの再取得ルールは運用方針で決める（1回のみ or 複数可）  
- FR-013：無効codeはエラー表示

### 5.3 箱庭（ガーデン）
- FR-020：2Dの箱庭フィールドを表示  
- FR-021：配置済みタネを座標で描画  
- FR-022：座標系は0〜1の正規化  
- FR-023：プレイヤー点を描画

### 5.4 タネの配置
- FR-030：未配置タネを箱庭内に配置  
- FR-031：配置座標をDBに保存  
- FR-032：配置済タネは再表示  
- FR-033：再配置・削除は将来拡張

### 5.5 プレイヤー点移動
- FR-040：十字キーで移動  
- FR-041：箱庭外に出ないように制御  
- FR-042：PCの矢印キーにも対応  
- FR-043：移動後に音量計算処理を呼ぶ

### 5.6 音の制御
- FR-050：タネごとに音源を持たせる  
- FR-051：距離で音量（0〜1）を算出  
- FR-052：一定距離以上は無音  
- FR-053：余裕があればステレオパン対応  
- FR-054：Web Audio APIまたはHowler.jsを利用

### 5.7 運営向け
- FR-060：QRコードデータ（code, seed_type）の登録  
- FR-061：タネ種類と音声ファイル紐付け  
- FR-062：タネ取得履歴をDB保存（実証用）

---

## 6. 非機能要件
- NFR-001：スマホ操作に最適化したUI  
- NFR-002：操作への応答は1秒以内  
- NFR-003：10〜50ユーザー同時利用に耐える  
- NFR-004：HTTPS必須  
- NFR-005：QRコードの `code` は推測困難なランダム値

## 8. DB設計（最小構成）

### 8.1 users

| カラム       | 型         | 説明 |
|--------------|------------|------|
| id           | bigint PK  | ユーザーID |
| google_uid   | string     | Googleのsub |
| name         | string     | 名前 |
| avatar_url   | string     | アイコン |
| created_at   | datetime   | 作成日時 |

### 8.2 qr_codes

| カラム      | 型         | 説明 |
|-------------|------------|------|
| id          | bigint PK  | QR ID |
| code        | string     | 埋め込むコード |
| seed_type   | string     | 音源タイプ |
| is_active   | boolean    | 有効フラグ |
| created_at  | datetime   | 作成日時 |

### 8.3 user_seeds

| カラム      | 型         | 説明 |
|-------------|------------|------|
| id          | bigint PK  | タネID |
| user_id     | bigint FK  | 所有ユーザー |
| qr_code_id  | bigint FK  | 取得元QR |
| seed_type   | string     | タネ種類 |
| status      | string     | acquired / planted |
| pos_x       | float      | 0〜1のX座標 |
| pos_y       | float      | 0〜1のY座標 |
| created_at  | datetime   | 取得日時 |

## 9. API一覧（簡易）

### POST /api/seed/claim
- 入力：`code`
- 出力：タネ情報
- 認証：必須

### GET /api/garden
- 出力：ユーザーのタネ情報（位置も含む）

### POST /api/garden/seed/place
- 入力：`user_seed_id`, `pos_x`, `pos_y`
- 処理：タネの位置更新
